## 摘要
同策略蒸馏（OPD）通过冻结教师模型在学生自身 rollout 上提供密集的 token 级监督，从而加速后训练。原始 OPD 对所有提示一律施加这种监督，而不检查教师模型对每个提示是否可靠。由于反向 KL 具有模式搜寻特性，一个自信却错误的教师可能引发强烈却带有误导性的更新。分布层面的代理指标（如熵或师生似然一致性）只能度量不确定性或一致性，并不能直接验证结果正确性。我们提出教师门控同策略蒸馏（TGOPD），其原则是：在接纳密集监督之前，应先于提示层面验证教师的可靠性。TGOPD 依据一小组由验证器打分的教师探测样本估计可靠性，并据此对每个提示单独路由：通过可靠性检验时走密集 OPD，否则走以验证器为依据的 GRPO。在数学、代码与指令遵循任务上，对 4B 与 35B 学生模型，TGOPD 在全部六个单领域设置中均优于原始 OPD，并在多领域训练下于两个规模上均取得更高的七基准平均成绩。通过将原本闲置的教师算力用于可靠性估计，TGOPD 还减少了异步 OPD 中教师侧的计算浪费，在实测的 4B 单领域运行中将教师节点 GPU 利用率从 9.8% 提升至 78.9%。

## Abstract
On-policy distillation (OPD) accelerates post-training by providing dense token-level supervision from a frozen teacher on the student's own rollouts. Vanilla OPD applies this supervision uniformly across prompts, without checking whether the teacher is reliable for each prompt. Because reverse KL is mode-seeking, a confidently wrong teacher can induce a strong yet misleading update. Distributional proxies, such as entropy or teacher-student likelihood agreement, measure uncertainty or agreement but do not directly verify outcome correctness. We introduce Teacher-Gated On-Policy Distillation (TGOPD), built on the principle that teacher reliability should be verified at the prompt level before dense supervision is admitted. TGOPD estimates reliability from a small set of verifier-scored teacher probes and routes each prompt exclusively to dense OPD when the reliability check passes or to verifier-grounded GRPO otherwise. Across 4B and 35B students in mathematics, code, and instruction following, TGOPD outperforms Vanilla OPD in all six single-domain settings and achieves higher seven-benchmark averages at both scales under multi-domain training. By using otherwise-idle teacher capacity for reliability estimation, TGOPD also reduces teacher-side compute waste in asynchronous OPD, increasing teacher-node GPU utilization from 9.8% to 78.9% in the measured 4B single-domain run.

## 1. 核心问题与整体含义

- **背景**：同策略蒸馏（On-Policy Distillation, OPD）让学生在自己的 rollout 上接受冻结教师模型的密集 token 级监督（反向 KL），相比 RLVR 的稀疏轨迹级奖励，可将学生达到教师水平的速度提升约一个数量级。
- **核心缺陷**：Vanilla OPD 对所有 prompt 一律施加教师监督，**不检查教师在该 prompt 上是否可靠**。由于反向 KL 具有 mode-seeking 特性，学生会集中拟合教师的高概率行为，一个"自信却错误"的教师会带来强而误导性的密集梯度。
- **诊断证据（Figure 2）**：以每 prompt 10 个离线教师响应的验证器通过率 $q_T^{(10)}$ 为可靠性标签：
  - 教师自置信度区分高低可靠性 prompt 的 AUROC 在代码上仅 0.51，数学上 0.73；
  - 在低可靠性区间（$q_T^{(10)}<0.5$），教师最高置信度采样响应仍有 84%（代码）/ 61%（数学）是错的——正是反向 KL 最容易传播的错误类型。
- **现有方法的两条路线均未直接解决问题**：
  - 分布层面证据（EOPD 高熵处前向 KL、TrOPD token 级信任域、REOPOLD 似然比/熵裁剪）度量的是不确定性、兼容性或优化风险，**不验证结果正确性**；
  - 结果层面证据（RG-OPD 轨迹级一致性、RLSD 方向-幅度分解、SPOT token 分支验证）作用于轨迹或 token 级，**未在密集监督施加前做 prompt 级准入决策**；多教师框架也只按领域路由而不验证所选教师。
- **第二个动机（系统层面）**：异步 OPD 中教师节点算力大量闲置——评分只是对已生成 token 的前向评估，远比学生自回归解码便宜，且必须等 rollout 批次就绪。实测 4B 运行教师节点平均 GPU 利用率仅 9.8%，59% 时间低于 5%。
- **整体含义**：提出"先验证、再蒸馏"——把教师闲置算力用于可靠性探测，在 prompt 级做准入决策，把监督信号路由到密集 OPD 或验证器接地的 GRPO。

## 2. 方法论

### 2.1 核心思想
- 以**结果证据**（验证器对教师完整 rollout 的打分）而非分布代理估计教师可靠性，在**提示级**做硬门控，通过则用密集 OPD，否则撤回教师监督、改用验证器接地的 GRPO。
- 两条分支**互斥路由**，绝不在同一 prompt 上相加或插值。

### 2.2 关键定义与估计
- **可靠性**：$R_T(x)=\mathbb{E}_{y\sim\pi_T(\cdot|x)}[r(x,y)]\in[0,1]$，即教师采样能解出该题的概率。
- **在线估计**：教师对同一 prompt 独立生成 $K_T$ 个探测 rollout $\{\hat y_k\}$，由同一验证器打分，通过率为
  $$q_T(x)=\frac{1}{K_T}\sum_{k=1}^{K_T} r(x,\hat y_k)$$
  由于探测 i.i.d. 且 $r$ 为二值，$K_T q_T(x)\sim\mathrm{Binomial}(K_T, R_T(x))$，故 $q_T$ 对任意预算无偏，方差为 $R_T(1-R_T)/K_T$。
- **硬门控**：$g(x)=\mathbb{1}[q_T(x)\ge\tau]$。因 $q_T$ 取值离散，操作上只有 $(\lceil\tau K_T\rceil, K_T)$ 有意义。主实验取 $K_T=3,\ \tau=2/3$（三分之二多数）。

### 2.3 门控条件监督路由
- **门开**（$q_T\ge\tau$）：用 OPD 优势 $\hat A^{\text{OPD}}_{i,t}=\beta\,\mathrm{sg}[\log\pi_T(y_{i,t}|x,y_{i,<t})-\log\pi_\theta(y_{i,t}|x,y_{i,<t})]$（式 1），密集 token 级、方向与幅度完整保留。
- **门关**：撤回教师监督，用 GRPO 组内中心化优势 $\hat A^{\text{GRPO}}_i=r(x,y_i)-\frac{1}{G}\sum_j r(x,y_j)$（式 2），对所有 token 相同；实现中**省略标准差归一化**（避免被组内奖励方差重缩放，属实现约定而非门控要求）。若组内奖励全同，中心化优势为零，该 prompt 不产生更新。
- **选择器形式**（式 6）：
  $$\hat A^{\text{TGOPD}}_{i,t}=g(x)\hat A^{\text{OPD}}_{i,t}+(1-g(x))\hat A^{\text{GRPO}}_{i,t}$$
  因 $g(x)\in\{0,1\}$，这是选择而非插值；Vanilla OPD 与纯 GRPO 是其两个退化端点。
- **优化目标**（式 7）：标准 PPO-clipped surrogate，优势在更新内固定；异步实现额外用 IcePop 抑制训练-推理概率失配（所有对比方法共享，非门控的一部分）。

### 2.4 算法与系统实现（Algorithm 1）
- 每个 prompt 同时进行：rollout 节点生成 $G$ 条学生轨迹（名义关键路径）；教师节点生成 $K_T$ 条探测并计算 $q_T(x)$。
- 两个候选优势**都预先算出**，但只有被选中的一个进入梯度。
- **探测与教师空闲窗口重叠**：$K_T$ 条探测在周期开始、与学生生成并发发起，大部分工作落在原本空闲的窗口内。
- **评分保持无条件**：教师仍对每个 prompt 做前向评分（成本低、避免数据依赖的流水线分支），验证器也照常给学生的 rollout 打分。TGOPD 相对 Vanilla OPD 的净增工作仅为 $K_T$ 条探测解码。
