## 摘要
高效推理的核心目标是改进准确率-效率前沿。然而，同时提升推理准确率和推理效率可能颇具挑战，因为这两个目标可能偏好不同的推理行为。独立进行后训练的模型已在准确率和效率方面展现出各自的优势。我们提出 Lightning Weave，这是一种后训练框架，通过在线策略蒸馏在单个学生模型中提取并组合这些独立习得的能力。每种习得的能力由模型在后训练前到所得专家模型之间的策略偏移来表示。Lightning Weave 在共享的学生 token 状态上组合对齐后的对数比值偏移，并使用 Tilted-Target DOPD 将缓存信号转换为稳定的学习目标。每个锚点对仅对缓存轨迹评分一次，从而无需同时服务多个实时锚模型即可进行后续学生模型训练。在多种学生模型以及数学和代码基准上，Lightning Weave 显著优于基础学生模型，并达到了当前最优的准确率-效率前沿。在 Qwen3.5-4B 上，它将 HMMT 2025 准确率从 59.2% 提升至 64.0%，同时响应 token 数减少 10.7%；并将 LiveCodeBench v5 准确率从 41.7% 提升至 54.2%，同时响应 token 数减少 9.6%。调整锚点信号的相对强度可得到强经验性的准确率-效率帕累托前沿。这些结果确立了 Lightning Weave 作为通过能力组合实现高效推理的一种新的实用路径。代码即将发布。

## Abstract
A core goal of efficient reasoning is to improve the accuracy-efficiency frontier. However, jointly improving reasoning accuracy and inference efficiency can be challenging, as the two objectives can favor different reasoning behaviors. Independently post-trained models already offer distinct strengths in accuracy and efficiency. We introduce Lightning Weave, a post-training framework that extracts and composes these independently learned capabilities in a single student through on-policy distillation. Each acquired capability is represented by the policy shift from the model before post-training to the resulting specialist. Lightning Weave combines aligned log-ratio shifts at shared student token states and uses Tilted-Target DOPD to convert the cached signals into a stable learning target. Each anchor pair scores the cached trajectories once, enabling subsequent student training without serving multiple live anchor models concurrently. Across diverse student models and benchmarks in mathematics and code, Lightning Weave substantially improves upon the base students and achieves a state-of-the-art accuracy-efficiency frontier. On Qwen3.5-4B, it raises HMMT 2025 accuracy from 59.2% to 64.0% with 10.7% fewer response tokens, and LiveCodeBench v5 accuracy from 41.7% to 54.2% with 9.6% fewer response tokens. Adjusting the relative strengths of the anchor signals yields a strong empirical accuracy-efficiency Pareto frontier. These results establish Lightning Weave as a new practical route to efficient reasoning through capability composition. Code will be released soon.

# Lightning Weave 论文深度总结

## 1. 核心问题与研究动机

- **研究背景**：大型推理模型在复杂任务上表现优异，但往往生成冗长的推理轨迹，带来高昂的推理成本。若强行缩短轨迹，又会因削弱有用探索而损害准确率。
- **核心矛盾**：高效推理的目标是改进"准确率–效率前沿"，但准确率与效率两个目标往往偏好**不同的推理行为**，联合优化困难，改进一方常以牺牲另一方为代价。
- **关键观察**：独立进行后训练（post-training）的模型已分别展现出准确率优势（如 Klear）或效率优势（如 DECS）。这提示了一条**互补路线**：将这些专家模型已学到的能力提取出来，通过策略蒸馏组合进单一学生模型。
- **核心研究问题**：*能否提取并组合通过独立后训练学到的能力，以提升学生模型的准确率–效率前沿？*

## 2. 方法论

### 2.1 核心思想
- 以 **在线策略蒸馏（OPD）** 为基础，将每种能力表示为一个 **锚点对（anchor pair）** 的策略偏移：即"后训练后的专家模型"与"后训练前的锚点模型"之间的 token 概率对数比值。
- 在**共享的学生 token 状态**上对齐并组合这些偏移，构造单一的学生学习目标，而无需模型参数匹配。

### 2.2 关键技术细节
- **策略偏移表示**：第 i 个锚点对 (π⁺ᵢ, π⁻ᵢ) 在状态 s 下对动作 a 的偏移为
  `rᵢ(a|s) = log π⁺ᵢ(a|s) − log π⁻ᵢ(a|s)`，它隔离了后训练带来的行为变化，而非端点策略本身。
- **多锚点加权组合**：`r_w(a|s) = Σᵢ wᵢ rᵢ(a|s)`，权重非负且归一化（Σwᵢ=1）。因为是对数密度比，加权组合等价于各锚点策略比值的加权乘积，而非教师分布的算术混合；一致的动作相互增强，冲突的改动被局部调和。
- **Tilted-Target DOPD**：针对朴素离线缓存 DOPD 的缺陷（学生偏离行为策略后，缓存动作无法正确估计 KL 正则项，导致目标处仍有非零梯度），论文构造显式倾斜目标：
  `q_w(a|s) ∝ π_b(a|s) · exp(r_w(a|s)/α)`
  训练目标为最小化学生到该目标的 KL 散度 `L = α·E[D_KL(π_θ ‖ q_w)]`。
- **理论保证**：通过指数倾斜恒等式证明，该 KL 目标与全分布的 KL 正则化 DOPD 目标等价（差一个与 θ 无关的常数），且在 `π_θ = q_w` 时损失与梯度同时为零，具有明确定义的**驻点/不动点**；当 K=1 时退化为单锚点 Tilted-Target DOPD。
- **离线缓存与效率**：每个锚点对只对缓存轨迹评分一次，之后训练仅需学生模型和缓存分数，无需并发服务 2K 个实时锚模型；调整权重即可得到不同的准确率–效率权衡。

### 2.3 算法流程（文字描述）
1. 用初始学生 π_b 对每个 prompt 采样轨迹并缓存 token 状态。
2. 所有锚点对在同一批缓存状态上评分，得到对齐后的 token 级偏移 rᵢ。
3. 按权重 w 组合偏移，对行为策略做指数倾斜，构造联合目标 q_w。
4. 在缓存状态上最小化学生到 q_w 的 KL（实现中采用有限候选集上的平方对数残差代理损失）。
5. 调整 w 可扫出准确率–效率帕累托前沿。

## 3. 实验设计

### 3.1 模型与锚点对
- **学生模型（5个）**：Qwen3-1.7B、Qwen3-4B、Qwen3-4B-Thinking-2507、Qwen3.5-4B、OLMo-3-7B-Think，跨多种规模与模型家族。
- **锚点对**：
  - 准确率导向：Qwen3-8B-Base → Klear-Reasoner-8B（Klear）；MiMo-7B-Base → MiMo-7B-RL-0530（MiMo-RL）。
  - 效率导向：DeepSeek-R1-Distill-Qwen-1.5B → DECS-1.5B（DECS）。

### 3.2 数据集与 Benchmark
- **训练数据**：数学取自 Skywork-OR1-RL-Data 的 math split（3,200 prompts）；代码取自 KlearReasoner-CodeSub-15K（3,200 prompts，长度过滤与去重，并筛查与 LCB v6 无重叠）。
- **评测 Benchmark**：
  - 数学：AIME 2024、AIME 2025、HMMT February 2025（各 30 题，数学采样 64 次，Avg@64）。
  - 代码：LiveCodeBench v5（279 题）、v6（131 题），采样 4 次（Avg@4，非 pass@4）。
- **指标**：准确率（Acc.）、平均响应 token 数（#Tok.）、准确率–效率得分（AES）。

### 3.3 对比方法
- 基础模型（Base）、单锚点策略（Klear-only、DECS-only、MiMo-RL）。
- 外部高效推理基线：SimpleSD、Qwen3-4B-Thinking-2507-Art、PromptCoT 2.0、模型插值（MI）。
- 消融对比：Online DOPD、Naive Offline、Data Mixture、Sequential Composition（两种顺序）。

## 4. 资源与算力

- 论文**明确报告了算力信息**（附录 B.3）：
  - 所有 GPU 阶段均使用 **单节点 8×H100 GPU**，bfloat16 精度。
  - 训练配置：100 轮 × 256 条轨迹，全局 batch size 64，共 400 次优化更新；离线训练对 12,800 条缓存轨迹回放 2 个 epoch（25,600 次使用）。
  - 在四个 Qwen3 设置下，Lightning Weave 相比在线 DOPD 减少 GPU 小时成本 **1.70–2.18×**；以 Qwen3-4B 三锚点成本推算，5 个组合配置的摊销成本降低 **4.58×**（21.47 vs 98.30 GPU 小时）。
  - 核心优势在于**避免训练时并发服务 2K 个实时锚模型**。
- 训练超参：Adam，学习率 1.0×10⁻⁶ 恒定，α=2.0，梯度裁剪 1.0，权重衰减 0.01。

- **实验规模**：5 个学生模型 × 5 个 benchmark 的主实验；Qwen3-4B-Thinking-2507 上 5 个内点权重的扫描；3 个锚点组合（Klear+DECS、Klear+MiMo-RL、DECS+MiMo-RL 及三锚点）；补充材料还在 Qwen3-1.7B、Qwen3.5-4B 上扩展了 MiMo-RL 组合。

- **充分性评估**：实验覆盖多种模型规模、家族、数学与代码两类任务，消融设计对照了在线/朴素离线/数据混合/顺序组合等关键变体，控制变量（初始化、prompt、轨迹预算、更新预算）较为严格，**整体较为充分且公平**。
- **客观性**：所有方法在相同评测协议下运行，AES 相对各自 base 模型计算并逐 benchmark 平均；但每个配置**仅训练一次**，未报告训练种子方差（评测的多次采样只反映解码方差）。

## 6. 主要结论与发现

- Lightning Weave 在所有 5 个学生模型上均取得**最高的 AES**，一致改善准确率–效率权衡，优于 base 与单锚点策略。
- **代表性结果**：
  - Qwen3-4B：平均准确率 +4.02 分，响应 token 减少 19.7%。
  - Qwen3-4B-Thinking-2507：平均准确率 +4.5 分，token 减少 9.0%。
  - Qwen3.5-4B：平均准确率 +9.70 分，token 减少 5.3%；HMMT 2025 从 59.2%→64.0%（token −10.7%），LCB v5 从 41.7%→54.2%（token −9.6%）。
  - OLMo-3-7B-Think：平均准确率 +3.74 分，token 减少 12.9%。
- **可控性**：调整 Klear–DECS 权重可得到一族学生策略，其非支配点构成经验**帕累托前沿**，在 AIME 2024 各 token 预算下均优于单锚点策略，紧预算下增益最大。
- **泛化性**：三锚点组合（Klear+DECS+MiMo-RL）取得最高 AES（0.42）；加入某锚点会使操作点朝对应能力方向移动。
- **消融结论**：Tilted-Target 与 Online DOPD 性能相当但训练更易部署；显著优于 Naive Offline（Klear +1.51 分、DECS +3.85 分）；顺序组合对顺序高度敏感，Lightning Weave 避免了混合稀释与顺序偏差。

## 7. 优点

- **方法创新**：以"策略偏移"而非端点参数或教师策略分布为组合对象，将能力组合与参数兼容性解耦；在共享学生状态上逐 token 显式指定多能力交互，优于数据混合与顺序组合。
- **理论严谨**：给出指数倾斜恒等式、目标等价性与不动点性质的完整证明，并构造反例说明朴素缓存代理缺乏固定点，动机清晰。
- **工程实用性**：离线缓存 + 单次锚点评分，无需并发服务多个实时锚模型，显著降低训练成本，且额外组合配置可摊销为仅学生训练。
- **可控性强**：权重扫描产生连续可调的准确率–效率前沿，用户可按预算选点。
- **实验扎实**：跨 5 个模型、5 个 benchmark，含充分消融与定性案例分析（Case Study），验证了互补能力确实被保留与整合。

## 8. 不足与局限

- **规模限制**：受算力约束，实验仅覆盖 <10B 参数模型，尚未验证在更大规模模型上是否成立。
- **锚点依赖**：方法要求同时获得"具备目标能力的后训练模型"及其"对应的 pre-anchor"，匹配锚点对在部分新任务（如智能体、工具使用）中可能不可得。
- **效率增益有限**：与专门优化效率的方法相比，Lightning Weave 的 token 节省幅度仍较小；它更多是改善整体前沿而非极致压缩。
- **训练方差未报告**：每个配置只训练一次，未报告训练种子方差，统计稳健性证据有限。
- **近似与适用范围**：理论保证针对全分布、固定缓存状态分布；实现使用 top-16 候选加残差项的有限支持代理损失、跨 tokenizer 掩码与数值截断，均为近似，论文也明确说明不保证任务准确率或长度的必然改善。
- **跨 tokenizer 对齐可能损失信息**：非原子 token 展开的位置会被掩码丢弃（主实验中保留 93.8–100%）。
